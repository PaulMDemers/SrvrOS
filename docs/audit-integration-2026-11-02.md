# Documentation and integration audit — 2026-11-02

## Scope and method

The inventory was the 135 tracked paths under `docs/`, nine root tracked files, four `.github/` files, three `initramfs/` files and `boot/limine.conf`. All inventoried paths were read programmatically. The documentation inventory at the start comprised 100 Markdown files, one HTML study, one JSON manifest and 33 files named `.png`; it includes current guides, dated history and image assets. Screening is not a line-by-line factual audit of the historical engineering records or physical-device evidence.

The offline Markdown checker examined 750 local inline file links and found no missing targets. A separate approximate GitHub-heading check examined 83 local Markdown fragments and found no unmatched headings; it is not a complete Markdown renderer. The gallery checker verified the three current screenshot hashes, dimensions and PNG headers. Independent header checks covered the other 30 PNG-named files, revealing one JPEG misnamed `.png` (below). The HTML parser checked 17 static `href`/`src` references, including fragments, with no missing local target or external resource. Dynamic behavior, visual layout, all remote links and every image's decoded pixels were not tested.

Manual cross-checks traced the README setup and acceptance boundaries, CI cadence and development guide against the workflow, Makefile and available hosted-run metadata; inspected issue/PR templates and security policy; compared third-party notices with submodule declarations and checkout state; and traced Limine paths, initramfs overlay, embedded exFAT fallback, ISO and USB image inputs. The scope complements the separate tooling audit and the integration owner's checks of embedded tool paths and Make target spelling. This private documentation pass did not download host dependencies, run a VM/shared build, write media, dispatch CI or perform a physical test. The coverage ledger records subsequent integrated host and guest verification by the coordinator.

## Findings and changes

- The workflow invoked `cli_smoke.py --restart-only` with its script default of **20 seconds** for boot, while `make smoke` uses `SMOKE_BOOT_WAIT ?= 180`. The separate invocation now passes `--boot-wait 180`; a static check compared it to the Makefile default. This prevents a more restrictive accidental boot deadline, but does not prove that the entire job will finish within its timeout.
- The CI cadence guide described configured triggers in the present tense despite repository-wide Actions being disabled. It now states those triggers are conditional, identifies the last successful hosted revision and records that current expanded coverage and the **40-minute** job deadline are unverified. Read-only `gh api repos/PaulMDemers/SrvrOS/actions/permissions` returned `enabled: false` on November 2; the workflow object itself reports `active`, which is not the repository-wide permission. No settings were changed.
- Hosted run `39516029574` succeeded for `a19ce5c5` on October 20; its job took 25 minutes 23 seconds and included fewer battery scenarios under a 30-minute job limit. The later non-cancelled run `39516771074` at `09207b0c` failed after 29 minutes 55 seconds in the battery stage because the guest reported `battery-service-test: FAIL USB progress proof`; its log ends with the harness assertion and exit code 1. It was configured for 40 minutes, so this is evidence of a test failure, not a demonstrated overall timeout. Current code, three additional isolated-filesystem cases, current build cost and runner variability leave present 40-minute sufficiency unknown. Run cancellation or any failed step prevents later checks; no current remote pass is claimed.
- `docs/design/desktop-study.png` contained JPEG bytes, not PNG. Its only Markdown reference and filename now use `.jpg`, preserving the original image bytes (SHA-256 `ece3b664f7af7c5f99c93ec067ecae87d9b1fb2ad103c46917471d7c34e2e746`). The remaining 32 `.png` assets passed signature/IHDR checks. This checks format identity, not visual accuracy or provenance.
- `initramfs/README` now explains that the generated archive overlays the compiled userspace init ELF on the source placeholder and embeds `srvros.exfat`. The Makefile copies the source tree first, then replaces `/init`, packs runtime ELF files and creates a ustar archive. The Limine ISO config names `/boot/srvros.elf` and `/boot/initramfs.tar`; the kernel locates the module and mounts the embedded exFAT fallback. This is a static wiring check, not a fresh image or boot test.

## Verification and residual limits

`python3 tools/check_docs.py` returned 750 checked links and zero errors after the changes. The workflow parsed with Ruby's YAML parser, its baseline job was present, and six multiline run blocks passed `bash -n`; static assertions confirmed the explicit restart wait and the 40-minute job setting. `git diff --check` passed. The image rename's hash was compared with `git show HEAD:docs/design/desktop-study.png`, and the resulting JPEG was identified by `file`.

The CI workflow is an intended local-coverage reference while Actions are disabled, not proof that its current sequence succeeds. The old success and subsequent distinct failure cannot predict runtime or outcomes for the current scope. Remote URLs, Markdown rendering quirks, actual screenshot decode/rendering, installed tool versions, real hardware support, licensing completeness of future binary redistributions and exact boot behavior remain outside the performed checks. The `docs/design/desktop-study.html` file describes itself as a prototype with sample state; static link inspection is not a usability or script security review. Historical claims remain attributed to their recorded source and are not upgraded to current acceptance by this audit.
