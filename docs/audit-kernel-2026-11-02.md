# Kernel, shared ABI and boot audit — 2026-11-02

Baseline: `dc0a3fef` (the checked-out `25cd19e5` adds an audit checkpoint; concurrent PTY and other work was present during the review). Scope inventory from `git ls-files kernel shared boot`: 221 files: 92 C, 7 assembly, 118 headers, 2 included source fragments, one linker script and one boot configuration. This includes 4 diagnostic files, 80 kernel headers, 104 files under kernel/src, 31 shared headers, the linker script and the boot config. The initial private review ran alongside the PTY work and did not use the shared build or VM. The combined integration results below supersede that initial execution limit.

## Confirmed findings

1. **High — unprivileged synchronous faults halted the OS (fixed and guest-tested).** `isr_dispatch_inner` previously called `halt_forever()` for every non-breakpoint exception regardless of `CS` privilege, so a ring-3 `ud2` or unmapped access stopped the machine. Selected ordinary CPL3 faults now leave user-safe admission, acquire the existing I/O exit gate, record a fatal signal, wake process wait queues, and use existing process exit machinery. #UD maps to SIGILL, arithmetic faults to SIGFPE, and ordinary protection/page faults to SIGSEGV. Kernel-context faults, NMIs, double faults and machine checks remain fatal. Host tests check selection, gate ordering, first fatal cause and the worker's join wake. The matched guest reaps an unmapped-write child, an invalid-instruction worker and a delayed fault after the initial thread calls pthread_exit. Synchronous signal handlers are not implemented.
2. **High — malformed ELF entry or segment can enter kernel fault paths or alias page-table indices (fixed).** The production loader accepted arbitrary `e_entry` and PT_LOAD virtual ranges. A host fixture invoking `load_elf_image_checked_impl` reproduced acceptance of a noncanonical entry on baseline; `usermode_enter` then supplies that value to `iretq`, which faults in the kernel. Noncanonical or upper-half segment addresses also entered the page walker without range validation. Validation now checks segment bounds, overflow, alignment, TLS alignment and that entry is within an executable load segment. The loader regression exercises invalid entries and segments, two separated valid segments, and full production loading of 136 existing userspace ELFs in an isolated Linux container. This is not a runtime execution test.
3. **High — noncanonical user pointers passed page-table validation (fixed).** Page-table indices discard high bits; an address such as `0x1000000001000` aliased mapped `0x1000`, passed `vmm_user_range_mapped`, and would cause a kernel #GP on copy. The range check now requires the entire buffer in lower canonical space. Page-walk permissions also combine U/S and R/W bits at every level, including large pages, rather than just the leaf. Synthetic table regressions fail against the baseline and pass after the fix. The public sysabi probe caused a kernel general-protection fault on the old image and returns a refused-buffer result on the rebuilt image.
4. **High — freeing a frame at or above physical 8 GiB halted the kernel.** The PMM bitmap covers the full managed address range and can allocate beyond frame 2,097,151, but the fixed-size tag array covered only those first 2,097,152 frames. `pmm_free_frame_range` classified higher allocated frames as reserved and halted. This affects ordinary user, page-table, DMA and stack allocations when memory above that boundary is used. The fix places one tag per frame next to the bitmap in reserved physical memory. A host regression initializes a real sparse memory map, allocates and releases frame 2,097,152, checks tag accounting and exercises the original first-fit oracle. This requires a contiguous usable range large enough for both metadata arrays; very sparse physical maps can increase metadata cost. The rebuilt 512 MiB guest boots and runs the integration suites. The above-8-GiB case is host-tested only.
5. **Medium — a truncated initramfs entry was exposed beyond the module.** `initramfs_init` previously published the size declared by a tar header before checking that its padded payload fits the provided module. Consumers could read past the archive. It now stops at a truncated entry before publishing it. Also, a 100-byte `./` name previously copied two bytes beyond its name field into the path; the copy is now bounded to the remaining 98 bytes. An AddressSanitizer/UndefinedBehaviorSanitizer host regression covers both cases. This validates bounds, not tar checksums or authenticity; a malformed entry stops subsequent parsing.

**High — a faulted worker could trigger ungated main-thread exit, now fixed.** When the initial thread has called `process_thread_exit` and waits for workers, a worker fault wakes it. That continuation could call `process_exit` after its IRQ-enabled wait without reacquiring the storage gate. All `process_exit` entries now mask interrupts, close user-safe admission and wait for storage before touching exit state. The host fixture checks gate ordering. The guest checks the retired initial thread and faulting worker path, and all four process-lifetime churn iterations pass. The exact competing dirty-file flush interleaving remains source-level evidence.

**High — user-buffer validation could race mapping changes, now fixed in the reviewed syscall paths.** `copy_from_user`, `copy_to_user` and the string helper now keep validation and access together under CPU0 interrupt exclusion, restoring the prior state between pages. A later invalidation may leave a copied prefix. Record-oriented callers retain exclusion through their entire output validation, copy and commit. The actual-source host fixture injects mapping changes and checks both refusal and IRQ restoration. It also checks scalar and positional regular-file transfers and PCM writes include validation in their existing masked operation.

Console reads use guarded output copies after keyboard waits. TCP/UDP transmit syscalls snapshot bounded input before network waits. Checked TCP read/peek, UDP receive and accept invoke output callbacks before advancing stream offsets, removing datagrams or accepting connections. All payload and metadata destinations are checked before any output is written. Network vector reads use the same transaction. Descriptor generation checks end waits after replacement even when an alias keeps the original endpoint alive, and closing an alias wakes those waiters. Accept also resolves its original listener identity after each wake and advances an existing receive offset correctly.

The actual network fixture checks refused copyout, retained datagrams and accepts, stream offsets, peek, metadata, blocked descriptor replacement and writer refusal. The syscall fixture checks revoked data and peer ranges, untouched sentinels, descriptor generations and transmit snapshot ownership. The QEMU network ABI probe unmaps a blocked UDP receiver's data or peer output, then retrieves the original datagram. Its duplicate/replacement case preserves both endpoints' datagrams. Full threadstress covers blocked pipe and PTY mappings and PTY master/slave descriptor replacement.

These protections rely on the current CPU0 execution model and scheduler wait/IRQ restoration contract. They do not implement SMP mapping pins. Console characters already fetched from the keyboard can be lost on output failure, while successful prior character copies return their prefix. Regular files retain their existing whole-operation masked copies. General latency bounds and asynchronous cross-CPU mutation are separate review work.

GCC also diagnosed a possibly uninitialized `delivered` array when zero rights are returned; it is now initialized to satisfy the warning and avoid dependence on a zero-length callback's treatment of the pointer. No behavioral defect was established for that warning.

## Methods and evidence

- Inventoried all 221 tracked paths and read every file as text in a scripted per-file scan for `TODO`/`FIXME`/`XXX`, unsafe string-format calls, memory-copy calls, inline assembly, allocation calls and user-pointer naming. This is a mechanical source-level check, not a manual line-by-line audit: the scan found zero TODO markers and unsafe string-format calls, two `memcpy`/`memmove` definitions, 206 inline-assembly tokens across 55 files, and 85 allocation-call matches across 21 files. Equivalent custom copy loops and different naming evade these patterns.
- Clang syntax checked all 92 C translation units with freestanding x86-64 flags, include paths and warnings as errors. `kernel/diagnostics/ap_probe.c` requires its actual build define `SRVROS_AP_PROBE`; without it, declarations are hidden, and with it the unit passes. All seven assembly files assembled privately. Headers and `.inc` files were checked only to the extent included by those translation units; linker and boot files were inventoried and scanned, not linked or booted.
- Ran Clang static analyzer on all 92 C translation units (including the AP probe define). It completed without compiler errors and produced 18 warnings in 11 units: eight fixed-address dereference reports in hardware/boot code, three syscall uninitialized-value reports, five dead-store reports, and null-dereference reports in GUI and scheduler. The fixed-address reports correspond to MMIO or explicit physical mappings; the GUI and scheduler paths depend on repeated lookup and slot/grow invariants respectively; syscall reports follow user-copy loops. These reports are leads, not proofs of either safety or defects. Analyzer does not model hardware, all scheduling behavior, or all configuration variants. The complete temporary diagnostic output was `/tmp/srvros-kernel-analyzer.log` during this session.
- Manually sampled PMM allocation/free/tag accounting and initramfs header/length handling, VMM user-range checks and syscall copy boundaries, scheduler thread allocation, GUI queue publication, exFAT directory traversal, the analyzer-reported MMIO sites, ELF load and segment validation, GDT selectors and user entry, IDT gates and ISR frames, page-table access rights, user copy and futex/wait revalidation, and boot configuration/linker layout. This does **not** constitute a complete manual review of every driver, startup/architecture path, process lifetime path, storage/network protocol, ABI contract, or concurrent interleaving. In particular native hardware ownership, DMA, packet parsing, ELF loading, process isolation and on-disk corruption handling need deeper independent review and runtime fixtures.
- Host PMM regression: `clang -std=c11 -O2 -Wall -Wextra -Werror -I kernel/include -I shared/include -I build/limine-protocol/include tools/test_pmm.c -o /tmp/srvros-test-pmm && /tmp/srvros-test-pmm` — passed.
- Initramfs regression: `clang -std=c11 -O1 -fsanitize=address,undefined -I kernel/include tools/test_initramfs.c kernel/src/initramfs.c -o /tmp/srvros-initramfs-test && /tmp/srvros-initramfs-test` — passed. No VM, physical hardware, fuzzing, cross-process isolation test, or production image verification was performed.

The findings above are the confirmed defects from this bounded pass, not a claim that the remaining code is safe. Concurrent worktree modifications mean the compiler/analyzer evidence describes the files as observed during this session, rather than a pristine checkout of the baseline.

## Static analyzer triage

All 18 initial reports were inspected against their paths and invariants; these explanations are not hardware or concurrency verification.

- `platform_audit.c:42,43`: two fixed virtual MMIO addresses; the diagnostic maps both GPU pages in `map_graphics` before use. `ioapic.c:46` and `lapic.c:50`: each controller register pointer is assigned only after its MMIO map succeeds. `laptop_probe.c:53,86,125`: each of three hardware-specific paths maps the two VA pages before the reads, after identity/resource gates. `main.c:313`: fixed-address VMM test writes only after successful mapping. These eight reports arise because the analyzer does not model the VMM; mapping success is not proof of correct hardware identity or device behavior.
- `syscall.c:221`: bytewise copy of `srv_meminfo` initialized by its six `uint64_t` fields; the struct has no inter-field or trailing padding in this ABI. `syscall.c:637`: analyzer assumes the byte copy skipped initialization but the later loop has `i < count`, and a successful copy writes `count * sizeof(iov[0])` bytes. `syscall.c:1639`: the same analyzer limitation applies to `nfds` poll entries; each entry is copied before use and `nfds` is bounded. These assessments assume the VMM/copy invariants and do not resolve races outside the traced path.
- `ahci.c:295`: initial `reason` is overwritten on every path that logs it; `exfat.c:809,819`: the loop's final `ok=false` overwrites those same failure values; `process_lifetime_test.c:53,86`: token/handle zeroing is dead on the shown success paths. Five dead stores do not change the observed behavior.
- `gui.c:193`: the analyzer assumes two `queue_for_pid` calls differ despite interrupts remaining masked when the first finds a queue; if allocation is needed, epoch and server are rechecked after the only IRQ-enabled window. `scheduler.c:696`: when `grow` is false, `thread_at(i)` addresses a published chunk (the scan uses the same `thread_at`); when true the new slot is assigned before use. Both depend on the current CPU0 ownership invariants and are not a proof under future SMP execution.

## Privilege boundary observations

GDT entries 3/4 and `iretq` use user data/code selectors `0x1b`/`0x23`, the TSS denies user I/O through an absent bitmap, and only IDT vector `0x80` is installed with DPL 3. ISR stubs save registers and clear direction before C dispatch. Address spaces copy upper PML4 entries from the kernel; lower user mappings are separately allocated. Futex validation and load are IRQ-serialized, and GUI wait copyout now guards each validation and access after waiting; the later checked network, file, PCM and console paths are described above. The user-range fix checks all paging-level permissions. Source inspection did not find an explicit CR0.WP enable; the active bootloader-supplied state was not measured, so supervisor write protection is unverified. The initial private pass did not verify these paths in a VM. Subsequent sysabi guests exercise invalid output and user-fault recovery; physical page protection and hardware interrupt recovery remain unverified.

Baseline-vs-current private host regressions: old PMM fails high-frame tag assertion, old initramfs fails truncated-entry assertion, old VMM accepts a noncanonical alias, and old production ELF loader accepts a noncanonical entry. Current versions pass. `tools/test_initramfs.c`, `tools/test_vmm_user_range.c`, `tools/test_user_fault.c` and `tools/test_process_fault.c` and `tools/test_syscall_user_copy.c` are wired into `test-core`; the loader cases extend its existing target. Linux GCC 16 tests were built in a disposable container with the repository mounted read-only and outputs under `/tmp`; no shared build artifacts were changed.
